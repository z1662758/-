# 铀供应链事中前端联动

本轮参考 `MACE-FE2` 中的人群聚集建模工作室和阶段 Skill 面板，保持当前系统的菜单布局与视觉规范。业务界面仅显示实验、参数、执行状态和依据，不显示数据实现方式。

场景边界、后端依据、术语指标和逐页优化记录见 [铀供应链事中场景与页面梳理](./uranium-during-scene-audit.md)。

## 当前运行链路

- 事中入口先流式显示需求理解、建模安排与下一步建议；用户可补充需求，只有点击“查看建模设定”才进入建模，不在回答完成后自动跳转。`during-session-*` 会话随方案保存，刷新可恢复。方案由 `mock/uraniumScenarioPlan.js` 构造，继续补充需求时复用该会话。
- 建模页展示供给、运输、制造、需求四个分组。关系画布与角色属性联动；环境参数经校验后写入 `useUraniumDuringStore.draft`，进入下一步自动保存。
- 实验启动使用 `useUraniumDemoStore.launchExperiment`。时间窗口、事件强度及迭代次数进入生成的实验结果，与年度推演和决策页共用一份数据。新增流程不依赖后端。
- “询问当前实验”携带实验 ID 进入对话。三个只读能力分别读取配置、年度指标和决策报告，输出依据卡片，并返回同一实验。
- 对话采用本地规则摘要与流式事件输出，尚未接入真实大模型。会话和依据存入浏览器存储，支持恢复、重命名、删除和中止。

## 后续接入点

`readUraniumExpertEvidence` 接受注入的 `readExperiment(id)`，只接受匹配 ID 且已完成的实验。`streamUraniumExpertChat` 当前生成 `tool_call`、`tool_result`、`text_delta`、`complete` 等事件，可后续替换为真实 Agent 事件流。组件不负责推演计算或后台技能调度。

目前场景数据与角色库仍为前端预置数据。窗口之外的年度使用边界基线延展，不代表历史观测；未覆盖的历史事件不能据此进行实证分析。关系画布按业务层级聚合，单个实体的完整角色在属性面板查看。

## 验证

运行 `node tests/uraniumDuring.test.mjs` 检查参数传递、指标同源、缺失值、实验 ID 校验、中止及流式事件顺序，包括需求对话完成前不开放建模方案。生产构建使用 `npm run build`。

布局回归覆盖建模、想定、实体、实验管理、态势、决策、案例和报告页的 1024 / 1280 / 1440 像素视口；建模面板按实际容器宽度换行，想定两栏独立滚动，工作台操作栏在文档流中预留空间，避免遮挡图表和时间轴。
